Ruling: `Pick` puts `mine` on the card before it calls `RollOnLoot` (through `ns.Safe`) and takes it back, returning false, when the call raises — the game ends the player's part (`CANCEL_LOOT_ROLL`) from inside `RollOnLoot` (a third-party emulator note built from probes of Forever says so; not checked in game), so whoever hears of `over` must already find the pick, and a card must never claim a pick the game never got — cost if wrong: the order of two messages.

Ruling: `reasonNeed` is set only when Need is not allowed and the game's code is above 0; the text is the client's `LOOT_ROLL_INELIGIBLE_REASON<n>`; the English fallback is verified for reason 1 only ("Your class may not roll need on this item.", quoted from a harness of the client's strings), any other number falls back to "You can't roll Need on this item." — cost if wrong: wording on a client without the globals.
Ruling: the item label goes beyond the brief in four places: shields and class relics (armor subclasses 6 to 11) read as their own word alone ("Shield", "Libram", ...), where "<type> <slot>" would give "Shields Off Hand"; a weapon whose slot and kind are the same word says it once ("Thrown"); an item without an equip slot reads as the game's item type ("Recipe", "Consumable"); an item level below 1 is nil, which the card shows as unknown — cost if wrong: one table and three branches in `Core/Items.lua`.
Ruling: `ns.Items.ID(link)` sits next to `Describe` (the card's `itemID`, and Task 5's matching by item) — cost if wrong: none.
Ruling: `Cards()` returns a new list on every call, so a caller may keep or sort it (unlike `Group.Members()`, which is shared and read-only); `START_LOOT_ROLL` for a roll that already has a live card adds nothing; the rebuild from `GetActiveLootRollIDs()` runs on every `PLAYER_ENTERING_WORLD`, not only after a reload, and adds a card only for a listed roll that has none; `CANCEL_LOOT_ROLL` ends the part on every card with that roll ID, and `CANCEL_ALL_LOOT_ROLLS` on every card with a roll ID, announcing only cards not yet over — cost if wrong: a duplicate or a missing card after a loading screen.
Ruling: the fake's roll helpers are `W.addRoll(rollID, spec, opts)` (R4), `W.items` with `W.cacheItem(itemID [, data])`, `W.itemLink(itemID, name, quality)` and `W.rolled`; `RollOnLoot` only records (the game's `CANCEL_LOOT_ROLL` is fired by a test when it matters), and a roll the game does not know answers nothing, a time left of 0 and no duration, as a third-party note on the client says it does — cost if wrong: none.
Known gap (check in game, design risk 5): Need or Greed on a soulbound item first shows Blizzard's bind confirmation (OK calls `ConfirmLootRoll`; Blizzard's dialog has Cancel and no handler for it). If the player cancels, Tutti's card already shows the pick and no buttons while the game's roll is still open, and only the hidden Blizzard popup could roll. A fix would listen to `CONFIRM_LOOT_ROLL`, take the pick back and set it again when `CANCEL_LOOT_ROLL` arrives; not built, as the brief and the design leave the dialog with Blizzard.
